# KnitKit2

Cimbar原版识别流程，加一个分段外壳：源端拆包、顺次播放；接收端保存完整段、生成待收短码，最后按顺序合并原文件。

## 使用

### 源端

打开 `dist/knitkit2.html`，直接通过Chrome的 `file://` 路径离线运行。全部资源内联，不需要安装Node/Python，不需要localhost、网络或旁边的源码。

1. 选择文件，默认每段1MiB；可选2、5、10、20MiB。
2. 先在接收端点击“读取”，再开始首轮。默认每段停留60秒，播完一轮暂停。
3. 接收端暂停后，复制待收短码，粘贴到源端并载入，开始补收轮。
4. 重复补收，直到接收端显示已收齐并提供原文件。

原版设置默认B模式、15帧/秒，未修改内核参数。默认60秒切段只是外壳定时，不是接收成功确认；接收未完成时需要补收或适当延长停留。源端不能隔空知道接收是否完成。

支持任务绑定的 `KK2M` 短码，也支持序号/范围，如 `1,3-5`。短码能核对文件任务；纯序号需要自己确认正在播放同一个文件。

亮屏辅助沿用现有前台Wake Lock逻辑，不保证后台标签或UOS系统策略下必然常亮。闪烁画面可能引起不适，请避免持续盯视。

### 接收端

HTTPS地址：https://jesseshawn9.github.io/knitkit-page/knitkit2/ 。iPhone使用Safari打开，点击“读取”，允许摄像头，对准源端的完整图案。

- 上方是原版Cimbar识别进度；取图数量不当作完成进度。
- 下方是已保存段数、待收段数与总进度。
- 首段完整校验后显示文件与待收列表；本轮结束后暂停，复制待收短码到源端补收。
- 收齐后自动逐段验证SHA-256、顺序和总大小，合并成原来的文件。
- 只在读取时启动原版引擎。查看已完成任务、重新下载文件，不会自动开启摄像头。

若取到画面持续增长、有效画面仍为0，打开“读取详情”查看送入/返回计数、像素输入和识别结果。这些只表示识别链路状态，不表示文件进度。读取中点击“采集诊断帧”，再点击“保存诊断文件”，可下载 `knitkit2-camera.json`：包含一张实际送入识别器的原始像素（Base64）、尺寸/格式和计数；不是缩放后的页面截图。只在手动点击时采集，不自动保存连续帧、不上传。诊断文件可能含有镜头内的敏感内容，分享前自行确认。保存诊断帧成功不等于扫描故障已修复。

取景预览铺满横向区域，不再用“宽屏”复选框包住一条竖向视频。它是预览排版，不会增加镜头本身的视角，也不改变原版送入识别器的像素格式与尺寸。摄像头仍按原版请求HD、连续曝光/对焦和15fps，实际输出取决于设备。原版横竖方向判断跟随整个页面，而非内嵌预览框；需要横向相机画面时，先横持设备，再点击读取。

已带走的旧源端仍兼容；新源端仅调整外壳布局，默认设置和分段协议不变。不把源端HTML或离线包发布到公网。

## 原版边界

当前直接复用本机Cimbar离线资源中的 `2026-08-21T2336` 接收、Worker和Zstandard脚本，以及v0.6.8原始JS/WASM。构建校验摘要，WASM字节和128MiB内存设置均不修改。

原版流程保持：VideoFrame取图，优先NV12/I420，必要时使用原版RGBA回退；4个原版图像Worker；原版自动模式识别、喷泉汇总与解压。没有自建符号重组，没有光学编号改写，没有手机/平板/电脑自适应档位，也没有4K强制参数。

构建时仅对接收脚本的WebCodecs取图接口作四处受校验的适配：等待 `copyTo()` 完成再转交缓冲区、使用 `visibleRect` 的原始像素尺寸而非旋转后的显示尺寸、复制失败时归还队列名额并报告错误。原始vendor快照、Worker、WASM、图案和默认参数都不修改。异步复制未完成就转交缓冲区，或混用旋转后的显示尺寸，会把错误的像素交给原版识别器；原先仅有桌面同步复制的测试未覆盖此情况。

适配层负责：把相同资源内联为独立HTML、启停相机、展示状态，以及把原版已经完整解出的文件交给分段外壳。每组作为独立的原版解码会话，切组时通过原版配置接口清理旧汇总状态并立即恢复同一模式，不改符号或编码参数；避免原版八槽及已完成编号缓存影响多组读取。解压完成前不切换汇总器，较晚返回的旧组图像不反向切组。每次重新点击读取都会建立新的原版会话，保留已完成段。原版诊断中可能包含字节内容，执行时在隔离页面中抑制这些日志，不向外发送内容。

## 保存与恢复

- 只把经过完整清单、任务ID、序号、长度和SHA-256校验的完整段保存到IndexedDB。
- 刷新或重开后，在同一浏览器、同一网址选择任务，可恢复已完成段并补收缺段。
- **不再提供额外的未完成段跨重播/重启续接。**当前未完成段遵循原版内存行为，切换、刷新、重启后可能需要重扫。
- 兼容旧版保存的完整段；不自动删除旧的未完成符号缓存，但不再用它们自动拼补。
- 不使用无痕模式，不清理网站数据。浏览器清理存储、换域名/端口或磁盘配额不足，都可能影响任务；本地存储不是永久备份。
- “删除任务”需确认。保存失败不算完成，混入其他任务不会拼入当前文件。

## 开发与验证

```sh
node cimbar/build.js
node cimbar/build.js --reader-only
node --test --test-concurrency=1 cimbar/test/*.test.cjs
```

源码在 `src/`，原版资源在 `vendor/`，构建产物在 `dist/`。不要手工改生成HTML。仅发布接收端时使用 `--reader-only`，保留已经交付的源端不变。

测试覆盖：任意二进制/中文文件名/空文件、165MiB拆包合并、缺段短码、乱序与重复、混入任务拒绝、旧完整段迁移、刷新恢复；实际原版VideoFrame/Worker链路顺次读取两个1MiB分段，原生中间进度与合并SHA-256校验；12个未完成流后的140个分段会话、编号回绕、迟到画面隔离与顺次解压。合成相机测试不能替代真实iPhone/UOS镜头、反光、对焦、热量和长期运行验收，不承诺每段必然60秒完成。

`capture.test.cjs` 复现异步复制、旋转显示尺寸及复制失败队列泄漏；`native.test.cjs` 使用真正的VideoFrame、90°旋转元数据和延迟复制，覆盖这次适配的完整接收链路。仍不能据此宣称真实iPhone已经通过。
