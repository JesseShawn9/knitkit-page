# CimbarPlus

Cimbar原版识别流程，加一个分段外壳：源端拆包、顺次播放；接收端保存完整段、生成待收短码，最后按顺序合并原文件。

## 使用

### 源端

打开 `dist/knitkit2.html`，直接通过Chrome的 `file://` 路径离线运行。全部资源内联，不需要安装Node/Python，不需要localhost、网络或旁边的源码。

1. 将文件拖进中心区域，或点击Choose file；默认每段1M，可选2M、5M、10M、20M。界面简写M，实际仍按1048576字节计算，分段协议不变。
2. 先在接收端点击Read，再点击Start。默认每段停留20秒；5至60秒每5秒一档，另有120、300、600秒，播放中也能实时调整，播完一轮暂停。
3. 接收端复制待补序号或短码；源端先Pause，再输入/粘贴到Repair code，点击Resume才提交并开始这一轮。输入过程中不会自行播放或切段。
4. 重复补收，直到接收端显示已收齐并提供原文件。

播放时可点击Next提前切到下一段，最后一段点击后结束本轮；暂停时点击Next只准备下一段，不自动开始。续杯按钮按每段容量乘20秒：1M显示+20s、2M显示+40s，依此类推；可连续点击，只延长当前段。切段后立即恢复Duration的配置时长，不把延长时间带给下一段。Duration仍可实时调整，不改编码、分段清单或原版帧率。默认仍为20秒；可按现场情况选择25、30秒等档位。

原版设置默认B模式、15帧/秒，未修改内核参数。20秒默认停留按用户要求留有余量，不是每台设备都能20秒收齐的保证；更大分段可增加停留时间。实时调整以本段已经播放的时长为基准，不重新准备或重置进度；调短到已播放时长以下会立即切段。定时切段不是接收成功确认，源端不能隔空知道手机何时收齐。接收不完整的段用实时短码补收。

源端不显示“离线分段”标签和“原版设置”入口。Density默认High (B)，虚拟机/远程显示场景可在开始前选择Low (Bu)：调用原版Bu模式，格子更少，在同样可用区域内放大显示；切换密度不会改变帧率。More默认收起，展开后Frame rate可选15/10/5/2/1fps，默认15fps，播放中调整不重新拆包或重置任务。不是压缩图片或降低清晰度；低密度每帧容量减少，低帧率单位时间画面数减少，必要时延长Duration。播放开始后锁定密度，Reset后可重新选择；分段清单、任务ID、补码和文件字节不变。Decoder仍沿用原版Auto检测，不增加外壳模式或相机参数。不能保证消除远程桌面压缩、网络波动或实机对焦问题。

界面采用近黑底与少量暖金色，两端分别标记Encoder与Decoder，全部操作文案为英文。Encoder右栏顺序为状态与进度、Settings配置（Repair code为最后一项）、操作按钮。底部提供Start/Pause、Next、续杯、Reset、Clear，没有单独的更换文件按钮。Reset保留文件和配置，重新准备首轮并暂停待播；Clear移除当前文件、播放位置和补收输入，回到中心重新选择。准备期间暂不允许重置或清空，以免中断原版编码。两项操作都不会清理接收端已保存任务。已准备后仍可将新文件拖到中心画面。

支持任务绑定的 `KK2M` 短码，也支持序号/范围，如 `1,3-5`。初次播放前、播放中及准备期间不可编辑补收框；暂停或一轮结束后可编辑。Resume只提交一次完整输入，成功准备后清空；无效内容保留并继续暂停，便于修改。没有输入时Resume接着原位置播放。有输入时从该补收列表第一段开始新一轮，清除上一段的额外续杯时间。源端表单隔离原版GLFW的全局键盘捕获，Backspace、Tab、全选和替换保持浏览器原生行为。短码能核对文件任务；纯序号需要自己确认正在播放同一个文件。

亮屏辅助沿用现有前台Wake Lock逻辑，不保证后台标签或UOS系统策略下必然常亮。闪烁画面可能引起不适，请避免持续盯视。

### 接收端

接收端HTTPS地址：https://jesseshawn9.github.io/knitkit-page/knitkit2/ 。iPhone使用Safari打开，点击Read，允许摄像头，对准源端的完整图案。

Decoder只有状态与进度、补收字段、四个平铺按钮。Read/Pause共用一个按钮；Copy IDs复制当前待补序号/范围，Copy code复制任务绑定短码；Clear确认后清除当前任务，没有Reset。缺段字段及原版进度实时更新。Saved tasks下拉框可恢复历史任务，不自动启动相机。扫描中复用同一套四按钮面板，去掉额外标题、右上角状态与折叠任务管理；不修改内嵌原版页面、相机或识别参数。

- 读取时显示完整的原版Cimbar接收页及原生进度条，不裁剪、拉伸或替换原版取景。
- 扫描中实时显示已存数量、待补编号和复制按钮；复制不会关闭相机。首段收齐之前还不能知道总分段，显示等待首段。
- 单段收齐后继续等下一段。摄像头由外壳独立持有：识别到新段后，只销毁旧原版解码页和Worker，新页复用同一条摄像头视频流，不重新申请相机。旧段未完成状态丢弃，已交给外壳的完整候选继续保存，已验证完整段不删除；下一段解码不等待这些候选保存完成。两次匹配的新原生流标识确认切段，原始字节和解码模式不改写。解码页重建仍有启动开销，不承诺零间隔。Pause、切后台、致命故障或全部校验合并成功才释放摄像头；旧页的延迟请求、已取消的权限结果不能重新打开相机。
- 外壳完成文件的待保存队列最多4项、合计48M；正在处理的同名候选不重复排队，处理结束即移除Blob引用和去重标记。拒收候选不留在队列，也不清除已保存段。队列溢出的候选保持待补，不能假记为已收齐。Pause丢弃排队的临时候选，正在进行的保存允许完成。
- 原版进度渲染保持不变；外层相同整数百分比不重复刷新。此外只读观察原版队列长度和Worker返回活动，不改取帧、模式或解码数据。队列超过原版上限且连续8秒没有Worker返回，或Worker发生未捕获错误时，只重建故障解码页，复用同一摄像头。故障重试60秒内最多两次；正常切段重建不消耗故障重试额度。没有读到有效图案或零进度本身不触发故障重启。没有网络同步信号，源端暂停、手动Next、续杯或定时结束的瞬间无法在手机端直接得知；切段丢弃发生在识别到新段之后，不能把本地倒计时冒充两端同步。
- Copy IDs和Copy code在保存分段时仍可用，不关闭相机。优先在点击时同步复制，失败再试Clipboard API；都失败时选中文本供手动复制，并明确显示Copy selected text，不假报成功。
- 收齐后自动逐段验证SHA-256、顺序和总大小，合并成原来的文件。
- 只在读取时启动原版引擎。查看已完成任务、重新下载文件，不会自动开启摄像头。

接收页占用与当前窗口相同的视口，方向判断、相机请求参数、预览比例、模式菜单和进度条沿用原版。外壳只持有共享相机，等四个原版图像Worker全部就绪后，才把视频流交给新解码页，避免热启动画面早于WASM初始化。不提供外壳自建的取帧统计、像素截图、宽屏适配或相机参数。

已带走的旧源端仍兼容，修复接收端不要求换源端。手动补收和按容量续杯的改进版源端单独本地交付；每段容量、任务清单和分段格式未变。不把源端HTML或离线包发布到公网。

外壳不再把30秒启动等待当作权限故障并自动关相机；收到原版进度或完整文件也能确认扫描已经开始，不依赖手机是否派发视频playing通知。启动等待提示不等于超时停机。切到后台仍会暂停，手机系统不保证后台相机可用。

就绪观察器只读video的播放状态与实际尺寸，避免playing事件丢失时画面已出现但外壳仍显示Waiting for camera。观察器不读取像素、不创建取帧回调；暂停销毁后停止。Looking for pattern仅表示相机有可用画面，不是识别成功；收到原版数据回报后才显示Receiving data。就绪观察与共享相机的生命周期管理彼此独立。

## 原版边界

当前使用 `2026-08-21T2336` 完整接收页、接收脚本、Worker和Zstandard脚本，以及v0.6.8原始JS/WASM。完整HTML于2026-11-17从 `https://cimbar.org/recv.html` 获取。构建校验摘要，原版接收脚本、CSS、WASM字节和128MiB内存设置均不修改。

原版流程保持：VideoFrame取图，优先NV12/I420，必要时使用原版RGBA回退；4个原版图像Worker；原版自动模式识别、喷泉汇总与解压。没有自建符号重组，没有光学编号改写，没有手机/平板/电脑自适应档位，也没有4K强制参数。

此前的四处WebCodecs适配已撤除。构建不修改原版的 `VideoFrame`、`copyTo()`、像素尺寸、模式选择或逐帧回调。唯一的相机接口适配是将原版页面的getUserMedia请求原样交给外壳持有，首次请求沿用原版约束，切段复用同一MediaStream；不修改相机分辨率、帧率或对焦参数。原版自身的兼容性与行为限制仍保留，不宣称外壳修复了原版所有浏览器问题。手机实机需要另行验证跨页面复用的实际效果。

外壳做资源内联、观察原生进度与原始FountainMetadata前四字节的流标识、接收原版已完整解压的文件，以及完整段校验、保存、补缺与合并。流标识仅用于判断是否整页重建，不作段落身份验证；只有完整清单/序号/长度/哈希校验通过才算收齐。不修改或拦截识别帧、不重排数据、不切换模式重置汇总器、不替换解压流程、不持久保存解码碎片。暂停/确认切段会停止相机、销毁内嵌页面和Worker；重新读取建立新的完整原版页面，已保存段不受影响。为保持单文件离线能力，省略可选PWA清单和Service Worker注册，并把原版Worker加载地址映射为内联资源；控制台日志只在本地被抑制，不发送内容。

这不是跨域调用 `cimbar.org` 的在线接口。浏览器不允许外壳读取另一个网站的下载结果；原版页面及其静态资源在同源隔离页面中运行，只有完成后的Blob和进度通知交给外壳。

## 保存与恢复

- 只把经过完整清单、任务ID、序号、长度和SHA-256校验的完整段保存到IndexedDB。新增段转为独立ArrayBuffer保存，写入后重新读取并核对长度及SHA-256，通过后才计入已保存；兼容已有Blob记录，无需清空历史任务。
- 刷新或重开后，在同一浏览器、同一网址选择任务，可恢复已完成段并补收缺段。
- Decoder不提供重置操作；Clear需要确认，才删除当前任务及其分段缓存。读取时先Pause再清空。
- **不再提供额外的未完成段跨重播/重启续接。**当前未完成段遵循原版内存行为，切换、刷新、重启后可能需要重扫。
- 不手工释放原版WASM内部仍在使用的内存，也不新增所谓“清内存线程”。原版未完成流缓存由原版管理；外壳只释放自己的候选引用，在明确故障恢复/暂停时销毁整个临时引擎。不能据此宣称每个失败帧都立即归还系统内存，或1G真实手机传输已验证。
- 兼容旧版保存的完整段；不自动删除旧的未完成符号缓存，但不再用它们自动拼补。
- 不使用无痕模式，不清理网站数据。浏览器清理存储、换域名/端口或磁盘配额不足，都可能影响任务；本地存储不是永久备份。
- 完成后不自动删除任务，避免尚未保存原文件就丢失恢复机会。确认原文件已保存后点击Clear并确认，可清除当前任务和分段缓存；其他任务保留。取消清空不改变进度。保存失败不算完成，混入其他任务不会拼入当前文件。
- 单段格式或内容校验失败，只跳过该候选段并继续扫描，已存段不清空。合并一次核对全部段，把所有缺失、损坏或无法读取的段一起恢复为待补，避免补完1才暴露2；有效段保留。存储空间不足等无法保存的错误仍会停止并提示处理。
- 保存/合并失败时区分缓存中没有该段、长度不符、内容摘要不符、内容无法读取；扫描浮层也显示具体原因。“缺失或损坏”不等于已经证明相机解码出坏内容。当前截图不能确定手机上的唯一根因，保存后回读与独立字节存储是外壳可靠性修复。

## 开发与验证

```sh
node cimbar/build.js
node cimbar/build.js --reader-only
node --test --test-concurrency=1 cimbar/test/*.test.cjs
```

源码在 `src/`，原版资源在 `vendor/`，构建产物在 `dist/`。不要手工改生成HTML。仅发布接收端时使用 `--reader-only`，保留已经交付的源端不变。

测试覆盖：任意二进制/中文文件名/空文件、165MiB拆包合并、缺段短码、乱序与重复、混入任务拒绝、旧完整段迁移、刷新恢复；原版VideoFrame/Worker链路顺次读取两个1MiB分段，原生中间进度与合并SHA-256校验；140个顺次完成分段及编号回绕。合成相机测试不能替代真实iPhone/UOS镜头、反光、对焦、热量和长期运行验收，不承诺每段必然60秒完成。

`runtime.test.cjs`逐字节检查原版脚本、WASM、CSS及启动参数；`capture.test.cjs`检查外壳不接管取帧/解码，原版进度保留，销毁解码页只停止Worker、不停止外壳摄像头；`diagnostic.test.cjs`检查手机横竖视口、无外部资源请求、首次原版相机参数和显式暂停释放相机。仍不能据此宣称真实iPhone已经通过。

`continuous.test.cjs`覆盖playing通知缺失、启动计时后继续扫描、实时待补/复制、坏候选段跳过、坏存储段恢复待补以及最终合并；`sender-replay.test.cjs`覆盖Pause后输入、Resume提交完整补码、无效输入保持暂停与默认编码参数不变。用户已报告新版可以在iPhone收齐3/4段；连续扫描修复仍需真实手机复验，不能用合成测试代替。

`native.test.cjs`不在两个1M分段之间人工Pause/Read，验证原版VideoFrame/Worker新流识别、同一相机复用、原生中间进度及最终文件。`handoff.test.cjs`覆盖慢保存积压、数量/字节上限、失败候选释放、故障恢复与过期回调隔离；`capture.test.cjs`覆盖无有效图案不误重启及持续满队列的恢复通知。`sender-timing.test.cjs`覆盖容量乘20秒的重复续杯、手动/自动Next、下一段恢复配置时长、暂停及重置。`window-bridge.test.cjs`核对只读标识观察、两帧确认和原始字节不变；`windows.test.cjs`核对八个未完成流丢弃、旧线程终止、同一相机轨道持续live、故障恢复不重开相机、完整段保留、补扫从零开始和最终字节。`camera.test.cjs`核对共享申请、原样参数与延迟权限结果清理；`camera-bridge.test.cjs`核对全部线程就绪后才交付视频流，以及旧页不能重新申请相机。`copy.test.cjs`核对实际剪贴板、权限回退和保存中复制。合成测试通过不等于已经修复真实iPhone卡段根因。

`workspace.test.cjs`覆盖中心拖拽与文件选择、5秒间隔档位及15秒实时调整、任务重置与确定性清单、清空取消待执行补收、准备期间操作保护；`style.test.cjs`覆盖17种桌面/移动端状态、文字对比度、长文件名和原版接收页完整视口。

`decoder.test.cjs`覆盖全英文四按钮布局、Read/Pause切换、序号/短码分别复制且不关相机、下拉恢复任务与Clear确认和视觉进度归零。剪贴板被拒绝时分别选中对应文本供手动复制，不停止扫描。

`display.test.cjs`直接点击当前Encoder的Start，截取真实播放时浏览器合成后的canvas显示，不手动调用编码器推进帧；把200000字节文件在1440×900、1366×768、1920×1080三种视口的B/Bu截图交给原版图像Worker、Sink与Zstd，核对原始文件字节和低密度格子的显示尺寸。`density.test.cjs`复用原生相机链路，验证Bu的两个1M分段经原版Auto检测、自动切段与合并；默认B模式另由`native.test.cjs`验证。这个屏幕级对照仍不等于物理手机镜头、反光、对焦或吞吐验收。`native.test.cjs`默认使用当前构建的Encoder，可显式用`KNIT_SENDER_PATH`再验证旧文件，避免测试无意绕开当前源端。
