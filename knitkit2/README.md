# KnitKit2 分批扩展

独立于第一期 KnitKit。保留 libcimbar v0.6.8 的编解码内核，在外层增加离线分段、编号选择、接收清单、本地暂存和自动合并。不改变官方内核的33MB单流容量，而是让每个任务由多份容量受控的独立分段组成。

## 使用

### 源端

打开 `dist/knitkit2.html`，使用 Chrome 直接双击、file:// 离线运行。不需要 Node、Python、localhost 或旁边的源码文件。

源端页面和源端离线包仅在本地交付，不部署到公网。只有接收端应用需要可信HTTPS；许可及构建源码作为独立材料保留。

1. 选择任意文件，默认每段1MiB，可在首次播放前改成2、5、10或20MiB。
2. 页面逐段计算校验值，自动准备第一段。整个文件不一次载入JS内存。
3. 先在接收端点击“读取”，再在源端点击“开始首轮”。默认每段停留60秒，自动切段，播完一轮后暂停。
4. 在接收端暂停，复制“待收短码”，粘贴到源端并点击“载入待收段”。也支持直接输入序号或范围，如 `1,3-5`，中文逗号、空格、换行均可分隔。重新读取，再开始补收轮；重复到收齐。
5. 源端不显示手动分段选择区，也无需逐段点击。首轮顺序播放，补收轮只按载入的待收序号自动播放。播放节奏、每段停留时长可随时调整；首次播放后锁定每段容量和画面密度，重新选择文件才重新规划任务。

播放节奏默认采用本包Cimbar原版的15帧/秒，换帧间隔按原版的 `Math.floor(1000 / fps)` 计算，默认66毫秒。实际帧率仍受屏幕刷新、浏览器调度和设备性能影响，不是接收吞吐率保证。

源端无法知道接收端是否完成，自动切段按时长，不是完成确认。默认1MiB/60秒不是速度或成功率承诺；当前段进度不足时可延长停留到120、300、600秒。新版接收端会暂存未完成段，下一轮确认是同一段后接续；无需更新已带走的源端。可多轮载入待收内容，不需要重新导入文件。短码会核对任务ID；直接输入序号时请自行确认当前文件任务，越界和非法内容仍会拒绝。

画面密度默认高（原生B，1040×1040）；也可选中（Bm，1040×736）或低（Bu，752×656）。接收端优先尝试高密度，首次定位时自动识别三种模式，兼容旧版源端。1MiB是1048576字节。

快速闪烁可能诱发光敏性癫痫或造成不适。不要长时间盯视图案。

### 接收端

`dist/knitkit2-reader.html` 同样包含全部JS、WASM和Worker代码，是独立HTML。与原版不同，不必部署旁边的JS/WASM文件。

1. 将此页放到可信HTTPS站点，Mac/iPhone浏览器打开后点击“读取”，允许摄像头。
2. 取景区上方直接显示原生喷泉解码进度条；下方显示已保存分段总进度。首段完整读到并校验后，显示文件名、分段总数和所有待收编号。
3. 已完成段显示绿色，待收短码随完成状态更新。首轮结束后暂停，复制短码给源端只播缺段，不要求按顺序。
4. 收齐后自动逐段复核SHA-256、按序组成Blob，并核对总大小。点击“保存原文件”。

已发布独立HTTPS接收地址：https://jesseshawn9.github.io/knitkit-page/knitkit2/ 。iPhone用Safari打开，点击“读取”并允许摄像头即可。旧首页和Pocket页面均未覆盖。

Mac本机仍可运行 `node cimbar/serve.js` 进行localhost验证；这不是源端使用要求。iPhone不能把普通HTTP IP或“文件”应用中的HTML当作可信HTTPS站点使用。

初次独立发布：Pages提交 `48d878a22f6722e8edafbe688b57acdc920d6ce2`，部署运行 `43801398036` 成功。对应源码包位于该HTTPS目录下的 `source.zip`。后续发布以构建产物、线上字节校验及部署结果为准，不能把启动正常视为真实iPhone镜头或速度验收。

接收取帧优先用视频帧回调，并有定时回退，不再依赖video.currentTime。请求后置高分辨率相机，实际尺寸由设备决定；完整原始画面按原始像素尺寸送入解码器，不裁切、不缩小。默认宽屏取景容器，视频始终等比例完整显示，可关闭“宽屏取景”恢复相机原比例；旋转或调整窗口不清空进度。竖向相机画面仍可能有左右留白，宽屏容器不能扩展镜头视角，可横持设备后观察相机实际输出。屏幕显示尺寸不等于内部解码尺寸。为避免无界内存占用，支持单边不超过8192像素、总像素不超过16777216，超过时明确报错而非偷偷缩图。界面显示原图尺寸、已取画面和有效画面，长时间未识别会给出定位提示，Worker超时会停止并报错。

本页只支持本扩展封装的Cimbar分段，不支持旧KnitKit二维码或未经封装的官方Cimbar文件。两个旧页面均保持不变。

## 暂存与恢复

- 每个完成段经过校验后才写入IndexedDB；完成状态以事务成功为准。
- 刷新或关闭浏览器后，正常浏览模式下可在原网址、同一浏览器中选择历史任务继续。
- 未完成段以去重后的喷泉符号存入IndexedDB，不保存相机图片/视频。切段、刷新、退出并重启浏览器后可以重建解码状态。显示进度以前先完成存储事务；尚在识别队列中的画面不等于已经暂存，关闭过快或死机可能丢失这几张未处理画面。
- 旧源端每次重播都会改变临时光学编号；它不是任务身份。接收端规范化符号编号，保留原模式、压缩长度和符号内容。完全一致的系统符号0作为候选续接锚点，不当作完整内容身份；连续前缀可用时会解出并验证完整清单。每段最终仍必须通过完整清单、序号、长度和SHA-256校验。
- 如果尚未捕获身份锚点，片段会单独显示“待确认分段”并暂存，不会仅凭相同大小/临时编号确认身份。后续有锚点、两份符号数量足够且没有冲突时，会尝试联合解码，只有完整校验通过才确认补齐；候选尝试不覆盖任一原缓存。重新播放时尽量从该段开头对准；极端漏掉身份画面的旧缓存不保证立刻能与换编号的重播合并。同一编号出现不同符号内容会分开保留并提示，不覆盖原进度。任务管理内可单独清理未确认缓存，需确认，完整段不受影响。
- 暂停不清空工作线程；切段不重启WASM、不丢弃首张识别结果。汇总器切换时清理原生喷泉槽位并回放该段已暂存符号，规避上游八槽碰撞及最后解压ID缓存。
- 不同浏览器、无痕模式、修改域名/协议/端口、清除网站数据、系统清理浏览器存储，均可能导致无法访问之前的任务。不要把浏览器存储当永久备份。
- 本地空间不足或保存失败会停止并报错，不会将未保存段标为完成。
- “删除此任务”需要确认，删除当前任务、完整段及已确认属于它的未完成符号。未确认归属的缓存不会冒充当前任务数据。

## 数据与安全边界

- 每段携带完整清单：原名、MIME、原大小、每段容量、所有分段SHA-256和任务ID。
- 任务ID是固定字段清单的SHA-256。同文件、同名字/MIME、同每段容量可重建同一任务；改名或更改容量会产生不同任务。
- 接收端拒绝其他任务混入，重复段不重复累计，损坏的分段不保存。
- 最终校验是逐段SHA-256加顺序、总大小检查；任务ID不是原文件整体SHA-256。测试会额外对原文件及合并文件计算完整SHA-256验证一致。
- 仅当前段和若干画面需要工作内存；最终下载仍受浏览器Blob、磁盘配额及设备资源限制，不保证任意大文件都能保存。
- 单段限20MiB，清单头限2MiB，防止异常输入占用无界内存。
- 不请求外部资源、不上传文件、不记录帧或内容。操作页面不显示许可展开区；许可、来源和源码获取信息独立保留在随包的LICENSE、NOTICE.txt、README及源码包中，未改动上游编译文件。
- 图像识别与喷泉汇总分离。手机默认1路识别，触屏Apple平板默认2路，桌面按硬件线程数开启1至4路识别，另有1路串行汇总。不是多个汇总器各扫各的；所有结果按取帧顺序交给同一个汇总器。原图在空闲识别线程上即时处理；在途画面最多为识别线程数的两倍，满时跳过新取帧，不无限缓存相机画面。手机较少线程是为控制每个图像WASM实例512MiB的内存预算；实际吞吐率仍需真机验证。

## 构建与验证

无新增npm依赖，构建工具只用于开发，不需要带到源端。

```sh
node cimbar/build.js
node cimbar/build.js --reader-only
node cimbar/test/protocol.test.cjs
node cimbar/test/browser.test.cjs
node cimbar/test/large-optical.test.cjs
node cimbar/test/resume.test.cjs
node cimbar/test/storage.test.cjs
node cimbar/test/profiles.test.cjs
```

浏览器测试默认复用本机已安装的Playwright。其他机器可通过 `PLAYWRIGHT_MODULE` 指向已安装模块。截图和报告默认写入 `/private/tmp/knitkit2-browser-check`，可用 `KNIT_TEST_OUTPUT` 改位置。

验证分层：

- 协议测试：二进制、中文文件名、空文件、确定性、乱序、重复、缺段、篡改；165MiB拆17段后合并，完整SHA-256一致。
- 浏览器测试：断网file://源端，真实WASM生成彩色图案，再由真实WASM从图像解码；接收端乱序/重复/混入其他任务、刷新/重新打开页面/退出并重启浏览器进程恢复、自动合并后的下载字节校验、桌面/窄屏排版。
- 大段图像测试：10MiB不可压缩随机二进制，真实WASM图案编解码，加入重复与跳过符号，最终SHA-256一致；这不是实际摄像头吞吐率测试。
- 合成相机测试：浏览器生成的视频轨道验证取帧、Worker处理、切段、暂停及轨道释放。合成相机不代表真实镜头、反光、透视、曝光或iOS系统行为已验证。
- 竖屏测试：1344×2240合成视频、图案偏离中央、冻结currentTime，验证视频帧回调及定时回退两条路径、自动Bu识别、完整原始像素读取、等比例预览、原生中间进度、下载SHA-256一致；不能替代Safari/iPhone真机验收。
- 原图内存测试：生成读页仅改变WASM内存段的两个字节，其余字节和导出接口一致；3840×2160合成视频通过实际取帧、识别、原生进度与文件SHA-256校验。真实iPhone的内存预算和速度仍需真机确认。
- 续接测试：原源端生成2份1MiB不可压缩内容，A扫约58%、B扫约58%且故意漏掉符号0，退出浏览器进程再打开；另加入损坏候选缓存。源端重编码改变临时ID后，各补扫不足以单独完成的剩余部分，最终合并SHA-256一致；损坏缓存不覆盖原数据。
- 存储测试：v1升级v2保留已有完整段，未完成符号幂等暂存、按任务清理、冲突符号不覆盖；模拟空间不足时不得报已保存。合成相机还故意让多线程结果乱序，验证切段保持工作线程及有界在途数量。
- 尚需真机验证：UOS源端，Mac摄像头，iPhone Safari，长期任务稳定性及真实吞吐率。没有据此承诺106KB/s。

## 上游

vendor保留未经修改的官方v0.6.8 JS/WASM发布资源。接收端构建只将生成WASM的固定内存从128MiB调整为512MiB，以容纳原始4K画面；编解码指令、其他WASM段和源端内核不变，构建会严格检查上游摘要及内存段布局。原图读取更占内存和计算资源，不保证所有iPhone系统版本都能维持相同吞吐率。许可证和源码位置见 `vendor/README.md` 与 `vendor/LICENSE`。保留版权/许可信息，主界面使用KnitKit2品牌，不声称第三方内核为自研。
